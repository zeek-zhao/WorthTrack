
# WorthTrack 需求规格（v2.0 · 模块化工具箱）

> 状态：**synced** ｜ 来源：Obsidian `40-项目/WorthTrack/WorthTrack-需求规格-v2.0.md` ｜ 同步日期：2026-10-31
> 决策过程见 [[模块化架构决策]]

## 1. 产品定位

**本地优先的个人工具箱。** 一个 App 装若干互不干扰的小工具，用户自己决定装哪些、开哪些；数据全部留在本机，无账号、无云、无遥测。

> [!note] 关于"个人助手"这个词
> 初稿曾定位为"个人助手"。**该说法被否决**：它不回答"用户一天里什么时候会打开它"，且暗示主动推送、信息聚合、跨模块编排——那是另一种产品（需要后台任务、通知、聚合层），不是本期范围。
> 工具箱是**被动**的：用户带着目的来，办完就走。这个定位下，"做得深"比"做得多"重要。

## 2. 模块清单

| 模块 id | 名称 | 一句话价值 | 核心动作 | 状态 |
|---|---|---|---|---|
| `finance` | 记账与资产 | 每笔钱有去处，现在有多少钱 | 记一笔 / 看净资产 | ✅ 已有（v1.0） |
| `watchlist` | 关注与提醒 | 我在等的价格到了没 | 加自选 / 设阈值 | 🆕 新建 |
| `notes` | 记事本 | 想到的事不会丢 | 写一条 | 🆕 新建 |
| `game` | 小游戏 | 等车时打发三分钟 | 开一局 | 🆕 新建（最小范围） |

**模块数量原则**：模块不是资产，完成度才是。每个模块必须达到"能独立当一个 App 用"的水准才允许上线；写不出「一句话价值 + 核心动作」的模块不进版本。

### 2.1 finance（已有，本期只做模块化改造）

保留 v1.0 全部能力：账户、交易、分类、周期账单、预算、报表、持仓、行情、净资产、备份恢复、CSV 导出、PIN 锁。
**内部结构不变**：仍是明细 / 报表 / 资产 / 投资 四个子 tab，作为模块内部导航存在。

### 2.2 watchlist（新建）

- **自选列表**：手动添加 A 股 / 场内基金代码，展示现价、涨跌幅、更新时间
- **持仓自动并入**：已有持仓默认出现在关注列表，但可单独隐藏（避免两处维护同一份数据）
- **阈值提醒**：每只标的可设「目标价上穿 / 下穿」或「涨跌幅超过 N%」
- **监测方式：仅前台**。App 打开时轮询（默认 30 秒，可关），命中阈值弹应用内提醒条；每次冷启动补检查一次
- **明确不做**：后台常驻监测、系统通知推送、服务端推送（见 §6）

### 2.3 notes（新建）

- 纯文本 + 轻量 Markdown（粗体 / 列表 / 标题），不做富文本、不做图片
- 置顶、搜索（标题 + 正文）、按更新时间排序
- **弱引用**：可给某只标的或某个账户挂一条笔记，存 `refType` + `refId` 字符串，**不建外键**
- 明确不做：附件、标签体系、双链、导出为 Markdown 文件（v2.x 可议）

### 2.4 game（新建，范围锁死）

- **一个**纯离线小游戏，无网络、无资源包、无内购、无排行榜
- 存在的意义是证明「新增模块 = 加一个目录 + 注册一行」，不是证明能做游戏
- 明确不做：第二个游戏、音频、在线对战、成就系统

## 3. 模块机制：装配，不是加载

> [!warning] 术语纠正
> 需求初稿写的是"动态加载模块"。**Flutter 做不到运行时加载代码**（Dart AOT；Android deferred components 仅限 Play 分发且对 Flutter 支持残缺；iOS 明令禁止）。因此本项目的机制定名为「**模块化装配 + 运行时门禁**」，文档与代码中禁止再出现"动态加载"字样，避免后续会话做出错误选型。

### 3.1 模块契约

```dart
abstract class AppModule {
  String get id;
  String get name;
  IconData get icon;
  int get defaultOrder;
  Set<String> get dependsOn;        // 依赖的模块 id
  Set<String> get ownedTables;      // 拥有的表 → 架构测试据此禁止跨模块直连
  List<RouteBase> get routes;
  List<Widget> settingsTiles(BuildContext); // 往系统设置页贡献条目
  Future<void> onEnable(ModuleContext ctx);
  Future<void> onDisable(ModuleContext ctx);
  Future<void> onClear(ModuleContext ctx);   // 清理数据，独立于停用
}
```

- **注册方式**：静态 `const modules = [...]`，不用 build_runner 生成。模块数量是个位数，显式注册表更不容易被改错。
- **依赖注入**：模块只通过 `ModuleContext` 拿 DB / 仓储 / 日志，**禁止 import `di.dart` 全局 Provider**。

### 3.2 门禁语义

| 动作 | 行为 | 数据 |
|---|---|---|
| **启用 / 停用** | 注册或注销路由与 launcher 入口；停用后不跑任何后台任务、不显示任何 UI | **一行不动** |
| **清理数据** | 独立动作，二次确认，明确告知将删除多少条记录 | 物理删除该模块 `ownedTables` 的数据 |

「用不用」和「删不删」是两个动词，UI 上必须是两个入口。合并会导致两类事故：只想眼不见心不烦却丢了流水；想彻底删掉却发现备份里还带着。

### 3.3 首页与导航

- **launcher 首页**：模块九宫格 + 常驻「记一笔 / 记一条」两个全局快捷动作（保证最高频动作永远 1 步）
- **冷启动恢复上次模块**，超过 30 分钟未使用则回 launcher
- 路由使用 `go_router` 的 `StatefulShellRoute.indexedStack`，**每个模块一个 branch，各自独立返回栈**
- **系统设置归 core**：PIN 锁、整库备份恢复、模块管理（启用/停用/清理/排序）不属任何模块；各模块只通过 `settingsTiles` 贡献自己的条目
  - ⚠️ 这条是硬约束：若把设置页归给 finance，停用 finance 后用户将失去模块管理入口，形成死锁

## 4. 数据边界

- **单库**（`schemaVersion` 升至 **2**），不拆库。理由：净资产 = 现金类余额 + 持仓市值，必须在同一一致性视图内读取；拆库会让核心口径失效，备份也从"拷一个文件"变成"多文件一致性快照"。
- **表所有权**：每张表有唯一所有者模块，声明在 `ownedTables`。跨模块**只能调对方公开的仓储接口**，禁止直接 join 别人的表。由一条架构测试守住（扫描跨模块 import 与表引用）。
- **Drift 的现实约束**：`@DriftDatabase(tables: [...])` 必须集中声明，`app_database.dart` 永远是全模块装配点。目标不是消灭它，而是做到「**表定义归模块，装配归中央**」，migration 收敛为各模块提供的 `MigrationStep` 列表。
- **弱引用**：跨模块关联一律存字符串（`refType` + `refId`），不建外键。模块被停用或清理时不破坏任何完整性约束。

### 4.1 本期 schema 变更（v1 → v2，本项目第一次写 `onUpgrade`）

| 表 | 所有者 | 说明 |
|---|---|---|
| `module_state` | core | 模块 id / 是否启用 / launcher 排序 / 首次启用时间。**必须随备份走**，故入库而非存文件 |
| `watchlist_items` | watchlist | 代码、名称、是否显示持仓、目标价上下限、涨跌幅阈值 |
| `notes` | notes | 标题、正文、置顶、`refType`、`refId`、时间戳 |

> PIN 凭据继续留在 `<应用支持目录>/pin_lock.json`：它是**设备本地凭据**，换机后本就不该带过去；而模块开关是**用户配置**，性质不同，不能照抄这个做法。

## 5. 目录结构

```
lib/
  core/                 # 共享内核：money、stream_utils、通用组件、路由壳
  data/db/              # AppDatabase：全模块装配点（唯一）
  modules/
    finance/{domain,data,ui}/
    watchlist/{domain,data,ui}/
    notes/{domain,data,ui}/
    game/{ui}/
  ui/launcher/          # launcher 首页、模块管理页
  ui/settings/          # 系统设置（core 级）
```

**搬迁要求**：现有 finance 代码整体迁入 `lib/modules/finance/`，作为**独立一次纯重构提交**——零功能变化，测试数必须与迁移前精确相等。搬迁必须在任何新模块落地之前完成。

## 6. 明确不做（v2.0）

- 运行时下载模块代码（Play Feature Delivery / 插件化 / WebView 壳）
- 后台常驻监测与系统通知推送（WorkManager / 前台服务 / 厂商白名单对抗）
- 服务端推送、云同步、多端同步、账号体系
- 第二个游戏、音频、成就系统
- 记事本的附件、标签体系、双链、Markdown 文件导出
- 港股 / 美股 / 场外基金行情

## 7. 非功能约束

| 维度 | 要求 |
|---|---|
| 模块隔离 | 停用任意模块后，其余模块功能完整可用；不出现启动崩溃、空 tab、死链 |
| 数据安全 | 停用不删数据；清理必须二次确认；备份/恢复覆盖所有已启用模块的数据 |
| 启动性能 | launcher 冷启动到可交互 ≤ 1.5s（4 模块规模）；模块页面懒加载 |
| 体积 | 单模块新增代码与资源 ≤ 2MB（game 除外，仍 ≤ 5MB） |
| 测试 | 每个模块自带单测与 Widget 测试；模块开关、清理、跨模块接口各有专门用例；碰钱路径集成测试只增不减 |
| 兼容 | Android 8.0+；Linux/Windows 桌面同款布局；schema v1 → v2 迁移必须有测试 |

## 8. 验收标准（v2.0 出口条件）

1. 4 个模块全部可用，`finance` 功能与 v1.0 完全等价（无回归）
2. 模块停用 / 启用 / 清理三条路径各有用例；停用 finance 后仍能进入模块管理页重新启用
3. schema v1 数据库升级到 v2 不丢数据，有自动化迁移测试
4. 架构测试通过：无跨模块直接表访问，无模块 import `di.dart`
5. CI 全绿；碰钱路径集成测试 ≥ 13 条且只增不减
6. 真机手测清单更新并通过；GitHub Release 存在 v2.0.0（签名 APK + Linux 包）
7. 断网状态下：记账、报表、记事、以缓存价查看盈亏全部可用（前台监测静默降级）
