# WorthTrack 项目计划与里程碑

> 状态：**synced** ｜ 来源：Obsidian `40-项目/WorthTrack/02-项目计划与里程碑.md` ｜ 同步日期：2026-10-25

## 1. 技术栈与架构

- **Flutter**（跨平台），**Riverpod** 状态管理，**Drift** ORM + SQLite
- 三层架构：UI → Repository → Drift DAO；单包不分模块
- 开发环境：WSL Ubuntu 24.04 本地验证 → push GitHub → Actions CI/发布

## 2. 里程碑（Issues 用 M1-M4 标签分组）

### M1 记账核心
账户管理、交易 CRUD、分类、流水列表、余额计算；Drift 建表与 Migration 基建；CI 流水线建立（format/analyze/test）。
**出口**：真机完成「建账户→记一笔→流水可见→余额正确」。

### M2 报表与预算
月/年报、分类占比、趋势图、月度预算与超支提示、周期账单自动生成、搜索筛选。

### M3 投资跟踪
持仓管理、PriceProvider（新浪/腾讯）+ 价格缓存 + 手动改价、盈亏计算、净资产总览、PIN 锁。

### M4 备份与打磨
db 备份恢复、CSV 导出、集成测试补齐、性能核查、v1.0.0 发布。

## 3. 质量门槛（CI 硬关卡）

1. `dart format --set-exit-if-changed` 通过
2. `flutter analyze` 无 error/warning
3. `flutter test` 全绿：业务逻辑层单测全覆盖（金额计算、盈亏、预算、周期账单、CSV）
4. 集成测试「碰钱路径全覆盖」（约 10-12 条：金额流转/预算扣除/周期账单生成/盈亏计算），CI 中 Android 模拟器跑；纯展示页只做单测+Widget 测试
5. 覆盖率 ≥80% 为目标，非硬卡

## 4. 流程约定

### 分支与 issue
- `main` + `feat/*` 功能分支；PR 触发 CI，绿灯才可合并，**任何代码不绕过 CI 进 main**
- 开发看板：Todo / In Progress / Done
- AI 工作闭环：领 issue → 开发 → 测试 → Conventional Commit 提交（关联 issue）→ 更新 docs/ai-changelog.md → 关 issue

### AI 改动记录三件套
1. **Conventional Commits**：feat/fix/refactor/docs/test 前缀
2. **docs/ai-changelog.md**：每次 AI 会话一条——任务、涉及文件、决策理由、验证结果
3. **issue 关联**：所有改动可回溯到 issue

### 发布
- 本地生成 keystore（不进仓库，密码进 GitHub Secrets）
- tag `vX.Y.Z`（语义化版本）触发 Actions：测试 → 签名 APK + Linux 压缩包 → 自动创建 GitHub Release
- 发布前：真机手测清单逐项过

### 文档规则
- **本 wiki = 唯一需求真源，AI 只从 wiki 读需求**
- Obsidian 为起草区：文档带 `draft`/`synced` 状态；需求变更在 Obsidian 起草 → 同步本 wiki（附 wiki git 历史回链）→ 才可开工
- 过程性笔记（踩坑、调试思路）只留 Obsidian，不进 wiki

## 5. 风险清单

| 风险 | 对策 |
|---|---|
| 新浪/腾讯接口变更或失效 | PriceProvider 抽象可换源；缓存价+手动改价兜底 |
| WSL 内 Android SDK/模拟器配置耗时 | 首个 issue 专门解决环境，文档化到本 wiki |
| AI 生成代码质量 | CI 硬门槛 + 碰钱路径测试 + issue 闭环，机器验收不靠人眼 |
| 文档双源漂移 | draft/synced 状态 + AI 只读 wiki 铁律 |
