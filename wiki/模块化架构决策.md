
# WorthTrack 模块化架构决策（2026-10-31 grill-me 定稿）

> 用途：记录"为什么这样选"以及"为什么不那样选"。需求规格写"做什么"，本页写"排除掉什么"。
> 对应需求：[[需求规格-v2.0]] ｜ 状态：**synced** 2026-10-31

## 决策一览

| # | 分支 | 决定 | 主要被否选项 |
|---|---|---|---|
| 1 | 产品定位 | 本地优先的**个人工具箱** | "个人助手"、"信息聚合助手" |
| 2 | 首页形态 | launcher + 全局快捷动作 + 恢复上次模块（30 分钟超时） | 纯 launcher、保留 5 tab |
| 3 | "动态加载" | **模块化装配 + 运行时门禁**（编译期全量编入） | 按需下载代码、WebView 插件化 |
| 4 | 数据边界 | **单库 + 表所有权**，跨模块只调接口 | 每模块一个 DB、事件总线 |
| 5 | 关闭语义 | **停用与清理拆开** | 关闭即删除、只能停用 |
| 6 | 目录结构 | 现有 finance 整体搬入 `lib/modules/finance/` | 用适配器接入不搬 |
| 7 | 监测方式 | **仅前台监测** | 后台常驻 + 通知、服务端推送 |
| 8 | 游戏范围 | **一个**最小离线小游戏 | 砍出本期、主题相关轻游戏 |

## 1. 为什么否掉"个人助手"

"助手"暗示三件事：主动推送、信息聚合、跨模块编排。三者都需要后台任务与通知层，而这两样恰好是本项目刻意不做的（本地优先、无云、无账号）。

更实际的判据：**它不回答"用户一天里什么时候会打开它"。** 工具箱是用户带着目的来的，助手是替用户盯着的。前者只需要"做得深"，后者需要"永远在线"。本期资源只够前者。

## 2. 为什么"动态加载"必须改词

Dart 是 AOT 编译，运行时没有代码加载能力：

- **Android deferred components**：仅支持 Play 分发，本项目是自签 APK 直装 + Linux 包，走不通；对 Flutter 的支持也长期残缺
- **iOS**：禁止下载并执行代码，无讨论空间
- **WebView 插件化**：真能热更，但要维护两套技术栈，除游戏外体验掉档，等于推翻现有架构

保留"加载"这个词的危害是**误导**：后来的实现者（含 AI 会话）会按"下载代码"设计，然后在 Android 上撞墙。改名为「装配 + 门禁」后，技术选型只剩一种可能，没有歧义空间。

## 3. 为什么拒绝拆库

净资产 = 现金类账户余额 + 持仓市值，必须在**同一一致性视图**内读取，否则会读到"钱已从 A 扣、尚未进 B"的中间态，净资产凭空少一笔。

拆库的连带成本：跨库查询变 N+1 或 ATTACH（Drift 不擅长）；备份从"拷一个文件"变成"多文件一致性快照"；CSV 导出要跨库拼装。**在财务应用里，库级解耦是反模式**——它用正确性换目录美观。

真正要防的不是 import，是**共享的可变状态与事务边界**。所以边界落在"表所有权 + 接口调用"上，而不是物理隔离。

## 4. 两个在拷问中暴露的设计漏洞

### 4.1 设置页不能归给任何模块

现有设置页同时装着 PIN 锁（core）、整库备份恢复（core）、CSV 导出（finance）、模块开关（core）。

若设置页随 finance 模块走，**停用 finance 就等于停用模块管理入口**，用户再也装不回来——死锁。

结论：系统设置归 core，模块只能通过 `settingsTiles` 贡献条目。

### 4.2 Drift 的单库必然有中央装配点

`@DriftDatabase(tables: [...])` 必须集中声明，`app_database.dart` 无法被模块化掉。

不去追"每个模块完全独立"这个不存在的目标；改为「表定义归模块，装配归中央」，migration 收敛为各模块的 `MigrationStep` 列表。**承认约束比假装绕过它更省事。**

## 5. 为什么只做前台监测

后台监测要同时对付四件事：通知权限、电池优化白名单、厂商杀后台（小米/华为/OPPO）、桌面端无统一方案。任一环节失效，用户看到的就是"它说会提醒我，但没提醒"——**信任损失大于功能收益**。

叠加一个硬限制：腾讯行情是未公开免费接口，5 秒级轮询会被限流甚至封 IP，"实时"本身有天花板。

因此本期定义为「打开 App 时告诉你哪只到了价」，并把这个限制**写进产品文案**，而不是让用户自己发现。

## 6. 搬迁策略

现有 finance 代码整体迁入 `lib/modules/finance/`，作为**独立一次纯重构提交**：

- `git mv` 保留历史 → 改 import → format / analyze / test 三关全绿
- **测试数必须与迁移前精确相等**（数量变了说明顺手改了行为）
- 该提交内不允许出现任何 `feat:`
- 必须在任何新模块落地之前完成，否则是在移动的地基上盖房子

## 7. 遗留风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 首次 `onUpgrade` | schema v1 → v2，此前从未写过迁移 | 专项迁移测试：造 v1 库 → 升级 → 逐表比对 |
| 游戏成本被低估 | 无游戏循环/音频/资源打包经验 | 范围锁死单文件、无资源；做不完就砍 |
| 工具箱完成度落差 | finance 有 299 个测试，新模块可能只有十几个 | 每个模块上线前定"最低完成度"清单 |
| 搬迁回归 | 65 个文件移动 | 纯重构提交 + 测试数断言 + 三关全绿 |
