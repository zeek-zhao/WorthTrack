# 发版说明模板（Release Notes）

> 用法：复制本文件到 `docs/release-notes/vX.Y.Z.md`，填完再打 tag；
> 内容同时贴进 GitHub Release 的正文（`scripts/poll_release.py` 只校验产物，不校验文案）。
>
> 写文案的三条规矩：
> 1. **先说用户能感知到什么**，再说实现（用户不关心 `VACUUM INTO`）。
> 2. **升级方式与数据影响必须写清楚**，尤其涉及数据结构的版本。
> 3. **已知问题不要藏**——写出来比让用户踩坑后再解释便宜得多。
